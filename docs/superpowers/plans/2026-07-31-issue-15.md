# Teams Toast Formatting (#15) Implementation Plan

> **For agentic workers:** this repo's protocol is `AGENTS.md`, not the generic
> executing-plans flow. Build with `/build-ticket 15` in a fresh window, one commit per
> task on a ticket branch, and stop before landing anything on `main`. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the macOS notification banner readable when a ticket summary is long, by
turning `headline` into a complete lead sentence and moving the summary to the end of the
message.

**Architecture:** Teams builds the toast from the chat message — HTML stripped, first ~4
lines kept. There is no separate notification field, so the only levers are wording,
order, and punctuation. Two halves: `src/cards.py` changes what the payload *says*
(repo-side, this plan); the Power Automate flow changes what order it *renders in*
(owner-side, documented here and pasted by the owner). The six-field payload contract is
unchanged.

**Tech Stack:** Python 3.12, stdlib + `requests`. No test suite. Power Automate flow HTML.

**Decision record:** `docs/superpowers/specs/2026-07-31-toast-formatting-design.md` —
owner-approved. This plan implements it; it does not re-decide it. Read it if a wording
question comes up.

## Global Constraints

- **No new payload fields and none removed.** The contract stays six fields
  (`ticket`, `summary`, `headline`, `subline`, `snippet`, `url`) so one flow covers every
  alert type.
- **No summary length cap, no truncation logic.** The owner explicitly passed on it.
- **Do not touch the digest's `Open Ticket #Digest` link.** Pre-existing, known, out of scope.
- **The flow edit is the owner's to perform.** The repo can only document it. A green
  `send-test.sh` proves the webhook works, not that a layout change landed — never claim
  otherwise.
- **Public repo.** No webhook URLs, no tokens, no Jira hostname in commits, issues, or
  pasted terminal output. The Task 1 verification snippet deliberately omits the `url`
  field for this reason.
- Copy strings must match the spec's table **exactly** — em dash, colon, and terminal
  period included.

### Task 1: `src/cards.py` — headline becomes the lead sentence

**Files:**
- Modify: `src/cards.py` (docstring lines 1–21, `_payload` 38–46, `comment_payload`
  49–59, `assigned_payload` 62–70, `digest_payload` 73–97, `reassigned_payload` 100–109)

**Interfaces:**
- Consumes: `RelevantComment` (`src/jira_client.py:30`) — fields `issue_key`,
  `issue_summary`, `comment_id`, `author`, `body`, `created`, `mentions_me`, plus a
  derived `url` property. Unchanged by this task.
- Produces: the same four public functions with the same signatures —
  `comment_payload(c) -> dict`, `assigned_payload(ticket, summary, url) -> dict`,
  `reassigned_payload(ticket, summary, url, new_assignee) -> dict`,
  `digest_payload(n_comments, n_assigned, n_reassigned) -> dict`. Only the *values* of
  `headline` and `subline` change, so `src/run.py` needs no edit.

- [ ] **Step 1: Sanitize `headline` in `_payload`**

`headline` now interpolates a Jira-supplied author name, so it needs the same treatment
as the other text fields.

```python
def _payload(ticket, summary, headline, subline, snippet, url) -> dict:
    return {
        "ticket": ticket,
        "summary": _sanitize(summary) or "(no summary)",
        "headline": _sanitize(headline),
        "subline": _sanitize(subline),
        "snippet": _sanitize(snippet),
        "url": url,
    }
```

- [ ] **Step 2: Rewrite `comment_payload`**

The headline absorbs what `subline` used to say, and names the ticket. The inline
`_sanitize(c.author)` goes — Step 1 now covers it, and sanitizing twice is dead work.

```python
def comment_payload(c: RelevantComment) -> dict:
    snippet = _sanitize(clean_snippet(c.body, config.SNIPPET_CHARS)) or "(no text body)"
    verb = "mentioned you on" if c.mentions_me else "commented on"
    return _payload(
        ticket=c.issue_key,
        summary=c.issue_summary,
        headline=f"{c.author} {verb} {c.issue_key}:",
        subline="",
        snippet=snippet,
        url=c.url,
    )
```

- [ ] **Step 3: Rewrite `assigned_payload`**

`subline` drops entirely — "This ticket is now on your plate" said nothing "Tag, you're
it" didn't, and it cost a line of the four-line budget.

```python
def assigned_payload(ticket: str, summary: str, url: str) -> dict:
    return _payload(
        ticket=ticket,
        summary=summary,
        headline=f"Tag, you're it — {ticket}.",
        subline="",
        snippet="",
        url=url,
    )
```

The separator is an em dash (`—`, U+2014), matching the spec table. `_sanitize` only
touches quotes, backslashes, control chars, and runs of whitespace, so the em dash and
the apostrophe in `you're` both survive.

- [ ] **Step 4: Rewrite `reassigned_payload`**

The colon goes so it reads as a sentence when flattened, and the `None` case gets its own
wording instead of the awkward "Now assigned to Unassigned." The `who = new_assignee or
"Unassigned"` line is deleted.

```python
def reassigned_payload(ticket: str, summary: str, url: str, new_assignee) -> dict:
    subline = f"Now assigned to {new_assignee}." if new_assignee else "Now unassigned."
    return _payload(
        ticket=ticket,
        summary=summary,
        headline=f"Not yours anymore :) {ticket}.",
        subline=subline,
        snippet="",
        url=url,
    )
```

- [ ] **Step 5: Punctuate `digest_payload`**

Punctuation only — the digest's field roles are unchanged, and its headline does not name
a ticket (there isn't one). Change exactly these two lines inside the existing
`_payload(...)` call:

```python
        headline="Update burst.",
        subline=", ".join(parts) + ".",
```

`parts` is never empty: `src/run.py:97` only calls this when
`total_pending > MAX_CARDS_PER_CYCLE`, so at least one count is non-zero. No guard.

- [ ] **Step 6: Rewrite the module docstring**

Replace lines 1–21 with the new field contract. The old `NOTE:` paragraph about
`mentionLine`/`author` field renames goes — that migration is long done, and it tells the
reader to update flow tokens that this change does not rename.

```python
"""Builds the flat data payloads sent to the Teams Workflows webhook.

The message LAYOUT lives in the Power Automate flow, which drops
@{triggerBody()?['field']} tokens into HTML. This script only sends the *data*.
Every alert kind shares one field contract so the flow never changes:

    ticket    - issue key (the flow's Open link splits it)
    summary   - issue summary; rendered LAST, as context
    headline  - the lead sentence: names the ticket, ends in terminal punctuation
                ("Bob commented on ABC-1:", "Tag, you're it — ABC-1.")
    subline   - optional second sentence ("Now assigned to Jane.")
    snippet   - comment text (empty for assignment events)
    url       - link to the ticket / focused comment

The macOS toast is this message flattened - HTML stripped, first ~4 lines kept -
so structure has to come from wording and punctuation, not markup. That's why the
headline carries the news and the summary comes last. Full reasoning:
docs/superpowers/specs/2026-07-31-toast-formatting-design.md

Interpolated values are sanitized (no quotes/backslashes/control chars) so they
can't break the card JSON when the flow drops them into a string literal.
"""
```

        created="2026-07-31T10:00:00.000+0000",

def show(label, p):

- [ ] **Step 2: Rewrite the paragraph under it (currently lines 68–72)**

Its claim that "plain comments lead with the ticket line" is false once every alert
carries a headline.

```markdown
   The notification banner is this message with the HTML stripped and only the first few
   lines kept, so every alert leads with `headline` — one complete sentence that already
   names the ticket. `subline` and `snippet` follow, and the ticket's own summary comes
   last: it's context rather than news, and a long one up top would push the comment text
   out of the banner entirely. The `concat(...)` lines emit their paragraph only when the
   field has content, so empty fields don't render blank gaps. The last line is the
   message's only hyperlink, standing in for the card's Open button.
```
